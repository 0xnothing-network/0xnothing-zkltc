# Maintenance audit — 2026-09-05

This pass fixes reproducible cache, upload authorization, wallet network-switch and filesystem cleanup races, and reduces redundant realtime work. It preserves the existing UI and onchain behavior. No TSX, CSS, Solidity, ABI, deployment address, dependency version or production configuration was changed by this pass.

## Scope and evidence

The starting tracked-file inventory contained 1,640 files. Excluding vendored contract libraries, generated bindings and build/index artifacts left 723 first-party source/configuration/documentation/assets files, including 533 tracked source files: web 223, wallet 122, 0xFi 95, mainnet 41, testnet contracts/subgraphs 44 and root tooling 8. This pass adds six regression-test files and one test helper, plus a regression case in the existing tooling suite.

The review combined Graft call graphs, targeted source inspection, compiler checks across the web/wallet projects, repository tests/builds, dependency audits and a local production-server browser smoke. It is not a claim that every line of vendored code, every document or every asset was manually reviewed. Generated output and secrets were not treated as source to edit. Codebase Memory coverage was checked for the evidence paths; stale graph metadata was backed by direct source reads, including the reported partial range in `apps/web/lib/marketplaceSubgraph.ts` at line 332. Graft was rebuilt after the changes.

Four wallet files were already modified at entry: `package.json`, `package-lock.json`, `public/manifest.json` and `tests/config/extension-config.test.ts`. Those changes were preserved.

## Changes

### Cache results cannot overwrite a newer forced refresh

`apps/web/lib/boundedCache.ts` previously allowed an ordinary pending load to overwrite a value written by a later forced refresh. The NFT, marketplace-listings and activity APIs seed shared entries after forced reads, so a slower earlier request could restore stale data to the cache.

Explicit `set` and `delete` now invalidate the previous flight's permission to write. Completion checks that it still owns the key. The returned promise includes cache writes and flight cleanup, so a following zero-TTL refresh starts fresh and TTL errors reject through the caller's promise instead of creating a detached unhandled rejection. Existing LRU eviction, same-key coalescing and saturation behavior are covered by regression tests.

### Returning to a tab does not restart an already-current query

`apps/web/lib/pollJitter.ts` now checks visibility, enabled state, data age and active fetch state when its delayed callback executes. Previously those checks ran only when the timer was scheduled. A fetch started or completed during the delay could therefore be needlessly restarted. Rejected background refreshes are handled, and pending timers are still removed on cleanup.

### Delayed duplicate upload authorizations are rejected

`apps/web/app/api/ipfs/upload/route.ts` now repeats the consumed/in-flight signature check immediately before acquiring the upload locks. Image validation and the reservation RPC yield between the first check and lock acquisition. Two requests with the same authorization could pass the initial check, then the slower one could upload again after the first finished and released its lock.

The regression runs the actual POST handler with controlled verification/RPC/Pinata boundaries. Before the fix the duplicate returned 201 and pinned twice; after the fix it returns 409. A failed upstream upload still permits a valid retry. Signing fields, onchain reservation requirements and fees remain unchanged.

### Candle aggregation avoids sorting the same collection inside the trade loop

`apps/web/features/pump/server/aggregate.ts` finds the nearest preceding candle in one scan instead of allocating, filtering and sorting an array for each new bucket. The predecessor lookup changes from O(C log C) to O(C) per new bucket, with no intermediate arrays. OHLC values, exact integer volume, transaction/log ordering and the non-mutating treatment of indexed candles are tested. This is an algorithmic improvement; no end-to-end production speedup percentage is claimed.

### Generated cleanup rejects linked parent directories

`scripts/lib/generated-cleanup.mjs` previously checked only whether the final target was a symlink. A parent junction could redirect an apparently in-workspace target outside the repository or bypass the tracked-file check through a different path.

Cleanup now rejects symlink/junction ancestors during preflight and checks ancestors again immediately before deletion. A Windows junction regression verifies both dry-run rejection and real-cleanup rejection, and confirms no earlier allowlisted target or outside sentinel was deleted. No user's source or existing build directories were removed during this pass.

### Wallet reads and approvals keep their original network context

`apps/wallet/src/core/services/history.ts` captured the selected RPC after awaiting storage. Switching networks during that wait could mark a pending transaction using another chain's receipt. `publicClientFor` in `src/core/rpc/client.ts` now resolves the requested profile without changing the selected network, and history captures that client before storage yields. History also deduplicates by hash and network together, preserving rows with the same hash on different profiles and the legacy LitVM fallback.

`src/core/services/tx.ts` now pins the read client for gas previews, including legacy gas-price fallback. The default `ensureAllowance` path keeps one execution context from allowance read through approval simulation, signing and receipt. Existing callers that already supply a pinned context continue to do so. Exact approval amounts, the sufficient-allowance no-op and the gas-padding formula are unchanged.

### RPC failures cannot publish an empty or partial NFT wallet

`apps/wallet/src/core/services/nfts.ts` pins one client for balance, token-ID and token-data reads. A failed balance or multicall item now rejects the load rather than returning an empty/partial success. The existing `useLiveRead` error path preserves the last good snapshot for the same account/network key. A verified zero balance still returns an empty list, and invalid artwork-size filtering remains unchanged.

The wallet regression suite executes actual service modules with controlled storage and RPC promises. Ten cases failed on the prior code; all thirteen new cases pass after the fixes, including the unchanged successful/no-op paths. No real key material, signing or broadcast is used by these tests.

### Cancelled token lookups do not exhaust the import budget

`apps/web/features/fi/lib/hooks/useImportedSwapAsset.ts` previously counted valid address candidates before their 280 ms debounce elapsed. Quickly changing candidates could exhaust the 20-address session budget without sending a request. Addresses now count only when a lookup starts, with the shared limit checked again at that point to handle concurrent pickers. The request timeout starts with the request and is cleared in `finally`. Metadata validation, the 20-address limit and UI strings remain unchanged.

## Remaining limits

- This is an engineering maintenance review, not a formal security certification or a guarantee that the repository has no further bugs.
- Upload replay state and rate limits remain in process memory. The repaired race is within one instance; global coordination across Worker instances would require shared durable state.
- Generic ERC-721 metadata still permits HTTPS DNS hostnames after rejecting IP literals/local hostname forms. The current code does not pin a resolved public IP, so deployment-level protection against DNS rebinding still needs validation. Arbitrary metadata-host compatibility was preserved.
- Contract tests were local. Optional live-fork test bodies depend on their configured RPC gates; passing the suite does not certify a new mainnet deployment.
- No Cloudflare deployment, extension installation, mobile-device run, live transaction or production load test was performed. Production p95 latency and post-transaction end-to-end freshness were not measured.
